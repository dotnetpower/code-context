## 1. Retrieval latency benchmark (AKS Store Demo, 8,960 pairs)

Across **8 fresh daemon sessions × 40 rounds × 28 tasks** (`8,960` correctness-checked off/on pairs) on the polyglot [AKS Store Demo](https://github.com/dotnetpower/aks-store-demo) corpus (`68` files, `172,244 B` across Go, Rust, JavaScript, Vue, TypeScript, and Python; pinned revision `3c3ba3bd999d0b2d78eece1adac84b712b7d9c4f`):

- **Mixed suite mean:** `3.996 ms` without CCTX → **`0.232 ms` with warm CCTX** (**`17.22×` faster**, 95% session-bootstrap CI **`17.04–17.40×`**, **`94.2%` less retrieval wall time**; up from `6.83×` / `0.557 ms` in v0.14).
- **Mixed suite p95:** `6.334 ms` off → **`0.355 ms` on**.
- **Cold sync median:** **`19.735 ms`** (down from `98.813 ms` in v0.14 — **`5.01×` faster**).

|---|---:|---:|---:|---:|
| Filename discovery (`code_files`) | 1,920 | 4.466 ms | **0.254 ms** | **17.57×** [17.29, 17.89] |

| Known small read + SHA-256 (`code_read`) | 1,920 | **0.081 ms** | 0.190 ms | **0.425×** [0.415, 0.438] — *slower* |
| **Fixed mixed suite (all tasks)** | **8,960** | **3.996 ms** | **0.232 ms** | **17.22×** [17.04, 17.40] |

:::caution[Honest scope & limitations]
- **Small known-file reads are 2.4× slower (`0.43×`) over daemon IPC** than direct in-process buffered reads (`0.081 ms` vs `0.190 ms`) because socket transport, policy checks, and JSON framing add fixed overhead. Known reads are intentionally kept inside the mixed suite rather than cherry-picked out.
- **Cold cache:** A cold `CACHE_MISS` plus host fallback had a **`4.409 ms` median**—not a cold-cache speedup. Ordinary callers never block on cold sync.
- **Hardware disclosure:** Measurements run on a nonexclusive Linux host without CPU pinning; hardware specifics are omitted for host privacy, so exact millisecond figures vary by machine.
:::

## 2. Lookup payload token suites (Rust & Python)

Replacing traditional two-step `rg -n` + 100-line or 200-line `view` reads with a single AST block-clamped `code_context` call (`radius=8..12`, `max_matches_per_file=5` with definition priority):

| Corpus & 6-Symbol Suite | Tool Calls (`rg+view` → `cctx`) | `rg` + 200L `view` | `rg` + 100L `view` | `cctx code_context` | Payload Token Reduction | Retrieval Time |
|---|---:|---:|---:|---:|---:|---:|
| **Rust** (`src/`, 20 files) | 20 → **6 (-70.0%)** | 25,133 tok | 15,028 tok | **4,031 tok** | **-73.2% to -84.0%** | 26.24 ms → **2.56 ms (10.3×)** |
| **Python** (506 files, 17.3k lines) | 15 → **6 (-60.0%)** | 24,609 tok | 13,997 tok | **2,141 tok** | **-84.7% to -91.3%** | 5.33 ms → **0.40 ms (13.16×)** |

## 5. Reproduce on your own machine

```sh
git clone https://github.com/dotnetpower/code-context.git
cd code-context
git clone https://github.com/dotnetpower/aks-store-demo.git ../aks-store-demo
git -C ../aks-store-demo checkout 3c3ba3bd999d0b2d78eece1adac84b712b7d9c4f

cargo build --locked --release
python3 -m venv .venv-benchmark
.venv-benchmark/bin/pip install -r benchmarks/requirements.txt
.venv-benchmark/bin/python benchmarks/benchmark.py \
  --root ../aks-store-demo --cctx target/release/cctx \
  --sessions 8 --rounds 40 --seed 20261023 \
  --output /tmp/cctx-benchmark-run
```

Raw observations and summary CSVs are published in the repository under [`benchmarks/results/aks-store-demo/`](https://github.com/dotnetpower/code-context/tree/main/benchmarks/results/aks-store-demo).
